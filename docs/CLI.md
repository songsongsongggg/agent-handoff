# CLI reference

Global `--state-dir PATH` must precede the command. Otherwise state uses the absolute path in `BATON_STATE_DIR`, falling back to `os.UserConfigDir()/agent-handoff`; the fallback is platform-specific. A relative `BATON_STATE_DIR` is rejected. Setting the variable in each client's native environment configuration keeps every client on the same state directory. Keep it outside the workspace and private. IDs are 32 lowercase hexadecimal characters returned by registration/creation. Session labels are non-secret caller-chosen identifiers and cannot be retargeted to a different task. All content is UTF-8 JSON. Normal structured output goes to stdout; diagnostics/private draft locations go to stderr. Nonzero exit means inspect the error; `check` also prints structured issues.

| Command | Behavior |
| --- | --- |
| `project register --path PATH` | Read-only workspace inspection; save a stable project ID in private state. Re-registering the same canonical root returns its existing ID. Register the real Git root. |
| `project list` | List registered identities; never select one by recency. |
| `task new --project ID --title TEXT --session LABEL --source CLIENT` | Create revision 1 and bind the explicit session. Initial content is incomplete until refined; writer ownership is not claimed yet. |
| `task list --project ID` | List independent tasks. |
| `resume --project ID --task ID --session LABEL [--claim]` | Check current HEAD/workspace, bind that session and print latest brief, including each saved WIP path's type, size and modification time. `--claim` registers the main writer. `--format json` returns the full latest envelope. `--budget N` is a positive character target, not a token estimate or hard truncation. |
| `handoff --project ID --task ID --to-session NEW_LABEL --to-source CLIENT` | Generate a copyable receiving-chat prompt. Requires a saved, unchanged workspace, no registered writer or pending revision, and a fresh label. Read-only: no reservation, binding, release, client launch or message sending. `--format json` returns the locator, observed HEAD and literal `resume_args` array. |
| `check --project ID --task ID --session LABEL` | Read-only inspection of latest revision, pending transaction, session freshness, saved-vs-current workspace and writer. Nonzero for discrepancies, including another task/session owning the writer. `workspace.file_changes` lists sorted `added`, `removed` and `metadata_changed` paths; these are metadata differences, not source diffs. No binding updates. |
| `checkpoint --project ID --task ID --session LABEL --source CLIENT --draft FILE --expect-revision N` | Preserve the content draft; CAS-save a complete new snapshot. Requires a current binding and writer claim. Source FILE is never modified. |
| `history --project ID --task ID [--revision N]` | Verify committed history chain; print metadata list or one full committed envelope. Pending orphans are not committed history; use `check`/error paths to inspect them. |
| `restore --project ID --task ID --session LABEL --source CLIENT --revision OLD --expect-revision N` | Copy OLD content into N+1 with current workspace and a restore reference. Does not restore code. Same binding/writer requirements as checkpoint. |
| `writer release --project ID --session LABEL` | Release the matching cooperative registration. Explicitly confirm the old client stopped before using another client's label for recovery. |
| `repair --project ID --task ID --expect-revision N` | Under storage lock, validate committed history and exactly one adjacent orphan, then advance HEAD. Invalid/multiple orphans, missing/corrupt HEAD or broken history require manual inspection. Never deletes/rewrites revisions. |
| `unlock --lock-token SHA256` | Remove the matching interrupted storage lock, only after confirming all baton processes stopped. Token is printed on lock contention. No time-based lock stealing. |

`resume`, `checkpoint` and `restore` accept `--accept-workspace-change` after actual file/Git inspection. Missing workspace or missing saved WIP cannot be overridden. Edits since a bound resume are normal on checkpoint; Git identity/branch/HEAD changes require explicit reconciliation. Deleted saved WIP must be recovered separately before continuing; intentional deletions/renames of saved WIP also trigger this conservative rule in v1.

For `handoff`, first save the current work and explicitly release its writer. Copy its entire output into the receiving chat. Paths and labels are literal JSON strings/arguments; use the receiving shell's quoting and never evaluate substitutions inside them. The observed revision is informational: the receiver must read latest with `resume` and save using the revision actually read. Readiness is checked at generation time, not reserved; another writer or workspace change can still block the later resume. Reusing a previously bound label requires the normal `resume`/`check` workflow, not `handoff`.

If a save fails before publication, previous HEAD remains valid and the retained draft can be reconciled. If it fails after revision publication, `check` reports a pending revision and `repair` can finalize it. If it fails after HEAD replacement, the new revision may already be committed; reload before retrying. On lock contention the original draft file remains intact (no internal copy can be made until the lock is acquired). Drafts have no automatic retention cleanup.

Snapshots skip ignored files and do not follow symlinks or inspect nested repository contents. Metadata cannot detect every same-size/mtime-preserving edit. See [storage limitations](DESIGN.md). No filesystem path or source bytes are uploaded by baton.
